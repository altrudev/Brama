# Як звертатися до BRAMA з пропозицією

## Позиціонування

Перший контакт не варто починати з переліку недоліків публічного порталу.

Сильніший підхід:

> Ми дослідили відкриту архітектуру взаємодії BRAMA та побудували публічний прототип, який може додати перевірний ланцюг "доказ -> людське рішення -> повноваження -> дія -> результат" без доступу до закритих даних і без збереження ворожого контенту. Хочемо запропонувати короткий технічний перегляд і синтетичний пілот.

Це позиціонує роботу як внесок, а не як зовнішній аудит державної системи.

## Кому звертатися спочатку

### 1. Команда Кібер Брами / Кіберполіція

Офіційний портал Кібер Брама вказує Департамент кіберполіції Національної поліції України як ініціатора проєкту.

Використати офіційні канали, опубліковані тут:

- https://stopfraud.gov.ua/about-the-project
- https://cyberpolice.gov.ua/contacts/

Для першого звернення краще використати загальний канал комунікації або форму "Задати питання", а не форму повідомлення про кіберінцидент.

### 2. Після первинної відповіді

Попросити передати пропозицію технічному або операційному представнику BRAMA, який знає:

- процес модерації;
- правила переходу від перевірки до дії;
- взаємодію з платформами;
- внутрішні вимоги до журналювання та звітності.

## Що надсилати

Перший пакет має бути коротким:

1. посилання на репозиторій;
2. `docs/PROPOSAL-UA.md`;
3. короткий опис уже працюючих модулів;
4. результати тестів та DDC-аудиту;
5. конкретне прохання: технічний перегляд + синтетичний пілот.

Не варто у першому листі просити доступ до внутрішніх API, баз даних або реальних доказів.

## Який пілот пропонувати

30–45 хвилин технічного перегляду достатньо, щоб пройти один синтетичний сценарій:

```text
сигнал
-> Evidence Capsule
-> два незалежні перегляди
-> VERIFIED
-> людське AUTHORIZED_FOR_ACTION
-> стандартизований пакет
-> штучний результат
-> офлайн proof bundle
-> незалежна перевірка
```

Це демонструє всю цінність без операційного ризику.

## Що залишити на другий етап

Після зацікавлення можна окремо обговорювати:

- адаптацію станів до процедур BRAMA;
- реальні категорії політик;
- C2PA/походження медіа;
- цифрові підписи рецензентів;
- платформні адаптери;
- панель аналітики ефективності;
- формати звітності;
- контрольований внутрішній адаптер.

## Якщо відповіді немає

Не дублювати повідомлення щодня.

Надіслати одне коротке повторне звернення через офіційний канал із посиланням на репозиторій та проханням передати його технічному представнику BRAMA.

Якщо первинний канал не спрацьовує, можна звернутися до партнерської сторони, зазначеної самим проєктом, але з формулюванням, що мета — знайти правильний технічний контакт, а не обійти команду BRAMA.
